# Postman Collection Update Proposal

## Change Summary
Added `title` field to response time analysis in AdminController analytics endpoint.

## Affected Endpoint
- **Route:** GET `/admin/analytics`
- **Method:** GET
- **Auth:** Bearer Token (JWT)

## New Field in Response
```json
{
  "responseTimeStats": [
    {
      "id": 1,
      "title": "Broken AC Unit",  // ← NEW FIELD
      "location": "Room 101",
      "submitted_to_assigned": 3600,
      "assigned_to_resolved": 7200,
      "total_time": 10800,
      // ... other fields
    }
  ]
}
```

## Recommended Test Assertions

Add these test scripts to the Analytics endpoints in Postman:

```javascript
// Test for Analytics - Monthly Filter
pm.test("Response time stats include title field", function () {
    var jsonData = pm.response.json();
    if (jsonData.responseTimeStats && jsonData.responseTimeStats.length > 0) {
        pm.expect(jsonData.responseTimeStats[0]).to.have.property('title');
        pm.expect(jsonData.responseTimeStats[0].title).to.be.a('string');
    }
});

pm.test("Title field is not null or empty", function () {
    var jsonData = pm.response.json();
    if (jsonData.responseTimeStats && jsonData.responseTimeStats.length > 0) {
        pm.expect(jsonData.responseTimeStats[0].title).to.not.be.null;
        pm.expect(jsonData.responseTimeStats[0].title.length).to.be.above(0);
    }
});
```

## Testing Checklist

- [ ] Login endpoint returns valid JWT token
- [ ] Analytics endpoint accepts JWT token
- [ ] Response includes `responseTimeStats` array
- [ ] Each item in `responseTimeStats` has `title` field
- [ ] Title field contains string value (not null)
- [ ] Title defaults to "N/A" when report.title is null
- [ ] All existing fields remain unchanged
- [ ] No breaking changes to API consumers

## Backward Compatibility

✅ **This change is backward compatible:**

- Uses null coalescing operator (`??`) with default value
- Existing API consumers will continue to work
- New consumers can utilize the title field
